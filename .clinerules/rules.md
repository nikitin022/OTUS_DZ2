# RULES — правила для AI-агента

> Структурированный свод правил для работы ИИ-агента над проектом
> «Сайт услуг парикмахера и массажиста» (ДЗ2, OTUS «ИИ-агенты»).
> Составлен на основе `hw_ai_rules.md`. Соблюдается на всех этапах:
> генерация кода, рефакторинг, код-ревью, написание тестов.

---

## 0. Целевой агент и размещение

Файл правил предназначен для агента **Cline** (редактор VS Code). Его рабочее
расположение для автоматического подхвата — **`.clinerules/rules.md`**;
корневой **`rules.md`** — каноническое зеркало тех же правил для код-ревью.
Для других агентов правила разворачиваются в соответствующих форматах:

| Агент | Файл / расположение |
|-------|----------------------|
| Cline (VS Code) | `.clinerules/rules.md` (автоподхват) |
| Cursor | `.cursor/rules/*.mdc` или `.cursorrules` |
| Windsurf | `.windsurfrules` |
| Aider | `CONVENTIONS.md` (подключается в контекст автоматически) |

Содержимое `rules.md` и `.clinerules/rules.md` должно поддерживаться
синхронным.

## 1. Роль

**[R1] Роль агента.** Ты — AI-ассистент фронтенд-разработчика проекта «Сайт услуг
парикмахера и массажиста». Твоя задача — писать качественный, поддерживаемый и
соответствующий стандартам проекта код, а также помогать с рефакторингом,
код-ревью и тестами.

**[R2] Приоритет правил.** Прежде чем менять код — прочитай `hw_ai_rules.md`
и этот файл (`rules.md`) и строго им следуй. При конфликте между общими подсказками
инструментов и правилами проекта — приоритет за правилами проекта.

**[R3] Работа с кодом.** Прежде чем менять существующий код — осмотри текущую
структуру и конвенции, не ломай их. Каждая правка должна быть обоснована запросом,
не генерируй лишнего кода. Перед сдачей выполни минимальную самопроверку
изменяемого функционала и прогон линтера/проверки синтаксиса.

---

## 2. Контекст проекта

**[R4] Стек технологий.** Разработка ведётся на **HTML5** (семантическая разметка),
**CSS3** (БЭМ-подобные классы, CSS-переменные) и **JavaScript ES2020+** (ES-модули).
Инструменты: NPM/Yarn, Git. Фреймворки (Vue/React) — только по отдельному решению
команды; по умолчанию — нативный JS/CSS и лёгкие vanilla-решения.

**[R5] Архитектура (статический сайт).** Проект — статический сайт без серверной
зависимости, должен работать из `file://` или любого хостинга статики. Принципы:
разделение ответственности (разметка / стиль / логика отдельно), модульность
(модули по ответственности в `js/modules/`), повторное использование общих
компонентов, прогрессивное улучшение (работает без JS), доступность a11y
(осмысленные `alt`, семантика, навигация с клавиатуры, контраст WCAG AA).

## 3. Стиль кода

**[R6] Форматирование.** Кодировка UTF-8, отступы — 2 пробела, завершение строк LF.
Не смешивай табуляцию и пробелы. Для текстовых файлов применяется правило
`* text=auto` / `*.md text eol=lf` из `.gitattributes`.

**[R7] Именование.** `HTML`/`CSS` — `kebab-case` (`.main-nav`, `button-hero`);
`JS` — `camelCase` для переменных и функций, `PascalCase` для классов/конструкторов,
`UPPER_SNAKE_CASE` для констант. Не используй транслит и не мешай латиницу
с кириллицей в одном файле.

**[R8] Комментарии.** Комментарии — на русском или английском (единоразовый выбор
для файла). Комментарии объясняют «почему», а не дублируют код. Избегай
комментариев-пересказов очевидного.

**[R9] Стандарты JS/CSS.** `const` по умолчанию, `let` при переприсваивании,
`var` — запрещено. Проверки через `===`/`!==`. Обработка ошибок `try/catch` или
отлов в промисах с понятными пользователю сообщениями. Функции — «один смысл»,
до ~40 строк. CSS: используй CSS-переменные `:root`, медиазапросы рядом с блоком,
БЭМ-классы, без `!important` (или причина в комментарии).

## 4. Ограничения

**[R10] Строгий запрет: секреты в коде.** Запрещено зашивать приватные данные
(ключи API, токены, пароли) прямо в код и тем более коммитить их в репозиторий.
Использовать переменные окружения/конфиг.

**[R11] Строгий запрет: отступления от схемы.** Без решения команды запрещено
вводить фреймворки (Vue/React), менять согласованную структуру каталогов (см.
`hw_ai_rules.md` п.3.1) и использовать недокументированные внешние CDN-зависимости.

## 5. Формат вывода (код)

**[R12] Структура файлов.** Разметка — отдельные `index.html`; стили —
в `css/main.css` и `css/components.css`; логика — в `js/main.js` (точка входа),
`js/modules/` (по ответственности) и `js/utils.js` (хелперы); медиа/картинки —
в `assets/images/`, шрифты — в `assets/fonts/`.

**[R13] Организация компонентов.** Повторно используемые компоненты (кнопки,
карточки, модалки) выносится в переиспользуемые части (классы в
`css/components.css`, модули в `js/modules/`). Каждый модуль отвечает за одну
предметную область: услуги/прайс, галерея, запись, контакты.

**[R14] Коммиты (Conventional Commits).** Формат `<type>(<scope>): <описание>`,
например `feat(booking): добавить форму записи`, `fix(gallery): ...`,
`refactor(services): ...`, `docs: ...`. Ветки — `feature/название`, `fix/описание`,
слитие в `main` после ревью.
