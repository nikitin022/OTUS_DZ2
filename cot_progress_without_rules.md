# CoT_PROCESS — применение Chain-of-Thought к разработке сайта

> Документ фиксирует применение техники **Chain-of-Thought (CoT)**
> к решению сложной задачи разработки «Сайт услуг парикмахера и массажиста».
> Проект — **ДЗ2** курса OTUS «ИИ-агенты».
> В ходе работы использовались **только** правила `hw_ai_rules.md`
> (файл `rules.md` исключён по требованию).

---

## 1. Выбранная сложная задача

> **Реализовать работающий статический сайт-визитку мастера** (парикмахер + массаж)
> со всеми разделами — услуги/прайс, галерея работ, форма записи, контакты —
> в полном соответствии с правилами проекта `hw_ai_rules.md`, включая
> адаптивность и доступность (a11y, прогрессивное улучшение).

**Почему задача «сложная»:** объединяет несколько самостоятельных подзадач
(структура данных, семантическая разметка, стилизация с переменными, модульная
JS-логика с валидацией), требует соблюдения архитектуры и стандартов качества
(a11y, адаптив, progressive enhancement) — это идеальный кандидат для декомпозиции.

---

## 2. Декомпозиция задачи на логические шаги (CoT)

Задача разбита на **5 последовательных шагов**. Каждый шаг — это отдельный промпт
по методологии проекта **RTCF** (Role → Task → Context → Format),
с последующей проверкой и conventional commit.

```
Шаг 1 (Архитектура и данные) ─▶ Шаг 2 (Разметка HTML) ─▶ Шаг 3 (Стили CSS)
        ─▶ Шаг 4 (Модульная JS-логика) ─▶ Шаг 5 (Тесты, проверка, документация)
```

| Шаг | Название | Файлы | Commit |
|-----|----------|-------|--------|
| 1 | Декомпозиция и схемы данных | (решения в этом документе) | — |
| 2 | Семантическая разметка | `without_rules/index.html` | `feat(html)` |
| 3 | Стилизация | `without_rules/css/main.css`, `without_rules/css/components.css` | `feat(css)` |
| 4 | Модульная JS-логика | `without_rules/js/main.js`, `without_rules/js/utils.js`, `without_rules/js/modules/*` | `feat(js)` |
| 5 | Тесты, проверка, документация | `without_rules/tests/booking.test.js`, этот файл | `test(booking)`, `docs` |

---

## 3. Шаг 1 — Декомпозиция задачи и схема данных

### 3.1 Промпт (RTCF)

```text
R: Ты — технический архитектор/тимлид проекта «Сайт услуг мастера».
T: Декомпозируй задачу «Реализовать главную страницу сайта» на подзадачи
   с критериями готовности, порядком и зависимостями.
C: Стек и структура — по hw_ai_rules.md (статический сайт file://,
   HTML5/CSS3/vanilla JS ES-модули; каталоги index.html,
   css/{main,components}.css, js/{main.js, modules/, utils.js},
   assets/images|fonts; БЭМ, 2 пробела, kebab-case/camelCase,
   а11y, progressive enhancement). Данные услуг/работ — JS-массивы.
F: Упорядоченный план подзадач (файлы → критерии приёмки → зависимости →
   тип commit), финальные схемы данных для услуг и галереи.
```

### 3.2 Результат

- Утверждён порядок исполнения: **1 → 2 → 3 → 4 → 5** (п. 2).
- Каждый модуль — одна предметная область (услуги, галерея, запись, контакты).
- **Схема услуги:** `{ id, name, category, price, duration, alt }`
  (цена в рублях — целое число, длительность в минутах).
- **Схема работы галереи:** `{ src, alt, caption }`.
- Данные вынесены в JS-модули (`services.js`, `gallery.js`) — это позволяет
  рендерить карточки и наполнять форму записи из единого источника.

## 4. Шаг 2 — Семантическая разметка `without_rules/index.html`

### 4.1 Промпт (RTCF)

```text
R: Ты — фронтенд-разработчик проекта (HTML5, семантика).
T: Создай index.html со всеми секциями: шапка/навигация, hero, услуги/прайс,
   галерея, о мастере, запись (форма), контакты, футер.
C: kebab-case-классы, progressive enhancement (работает без JS),
   a11y (семантика, alt, label для полей, навигация с клавиатуры).
   Скрипты type="module" + defer, линки на css/main.css и css/components.css.
F: Полный валидный HTML, секции-комментарии, изображения из assets/images/.
```

### 4.2 Результат

Создан `without_rules/index.html` (165 строк) со всеми секциями:
`header` (логотип, навигация, CTA), `hero`, `services`, `gallery` (с лайтбоксом),
`about`, `booking` (форма с `label` для каждого поля), `contacts`, `footer`.
Семантика: `<header>`, `<nav>`, `<main>`, `<section>`, `<address>`, `aria-label`,
`role="status"`/`aria-live` для статуса формы, `aria-modal` лайтбокс.

**Commit:** `feat(html): разметка главной страницы со всеми секциями`.
---

## 5. Шаг 3 — Стилизация CSS

### 5.1 Промпт (RTCF)

```text
R: Ты — CSS-разработчик проекта (БЭМ, CSS-переменные).
T: Напиши стили в css/main.css (палитра и отступы в :root) и
   css/components.css (карточки, кнопки, форма, галерея).
C: БЭМ-классы, медиазапросы рядом с блоками, без !important,
   контраст WCAG AA, адаптив mobile/desktop.
F: Полные файлы, список переменных, breakpoint.
```

### 5.2 Результат

- `without_rules/css/main.css` — переменные `:root` (палитра, отступы, радиусы, типографика),
  базовая типографика, шапка/навигация, hero, «о мастере», контакты, футер.
- `without_rules/css/components.css` — переиспользуемые кнопки (`button--primary/ghost`),
  карточки услуг, галерея, лайтбокс, форма записи.
- Медиазапросы рядом с блоками; breakpoint 768px (планшет) и 640px (мобильная форма).
- Контраст текста/фона соответствует WCAG AA.

**Commit:** `feat(css): стилизация страницы с переменными и компонентами`.

---

## 6. Шаг 4 — Модульная JS-логика

### 6.1 Промпт (RTCF)

```text
R: Ты — vanilla JS-разработчик (ES-модули).
T: Создай модули: services.js (рендер прайса, наполнение select),
   gallery.js (лайтбокс + клавиатура), booking.js (валидация, понятные
   сообщения), contacts.js (год в футере), utils.js (хелперы),
   main.js (инициализация).
C: const/let, ===, try/catch, функции ≤40 строк «одна — один смысл»,
   a11y, progressive enhancement.
F: Полные модули с export, инструкция инициализации из main.js.
```

### 6.2 Результат

Созданы файлы:
- `without_rules/js/utils.js` — `getElementById`, `formatPrice`, `SERVICE_CATEGORIES`, `isNonEmptyString`.
- `without_rules/js/modules/services.js` — массив `SERVICES` (7 услуг), `renderServices()`,
  `populateBookingSelect()`.
- `without_rules/js/modules/gallery.js` — массив `WORKS` (6 работ), `initGallery()` с лайтбоксом,
  закрытием по Esc/клику по фону.
- `without_rules/js/modules/booking.js` — `validateBooking()` (чистая функция), `initBooking()`.
- `without_rules/js/modules/contacts.js` — `initContacts()` (текущий год в футере).
- `without_rules/js/main.js` — точка входа `initApp()`.

Все модули безопасно завершаются при отсутствии контейнера (progressive enhancement).
Добавлены placeholder-изображения (SVG) в `without_rules/assets/images/`.

В ходе шага выявлен и исправлен дефект: кнопка закрытия лайтбокса искалась
через `grid.querySelector`, хотя находится в `lightbox` — исправлено на
`lightbox.querySelector` до этапа проверок.

**Commit:** `feat(js): модули услуг, галереи, записи и контактов + placeholder`.

## 7. Шаг 5 — Тесты, проверка, документация

### 7.1 Промпт (RTCF)

```text
R: Ты — QA-инженер + code-reviewer проекта.
T: Проверь валидность HTML/CSS/JS, отсутствие синтаксических ошибок;
   напиши юнит-тесты для validateBooking без внешнего фреймворка.
C: Правила по hw_ai_rules.md (п. 5.3 — проверки перед сдачей).
F: Отчёт о проверке, покрытые/непокрытые кейсы, создание документации
   cot_progress_without_rules.md.
```

### 7.2 Результат проверок

- **Синтаксис JS:** `node --check` для всех 6 файлов — без ошибок.
- **Юнит-тесты:** `node --test without_rules/tests/booking.test.js` — **8/8 прошли**.
  Покрытые кейсы: валидная форма, пустое имя, пустой/некорректный телефон,
  телефон без разделителей, невыбранная услуга, пустая дата, множественные ошибки.
- **Файлы/структура:** соответствуют `hw_ai_rules.md` п. 3.1.

**Commit:** `test(booking): юнит-тесты валидации формы записи`.

---

## 8. Итоговые выводы о применении CoT

1. **Декомпозиция снизила риск ошибок.** Разделение на HTML → CSS → JS → тесты
   позволило проверять и коммитить каждый слой отдельно (5 коммитов) и находить
   дефекты на ранних этапах (например, неверный поиск кнопки закрытия лайтбокса
   в `gallery.js` исправлен на шаге 4 до проверок).
2. **Чистые функции облегчают тестирование.** Выделение `validateBooking()` без
   DOM-зависимостей позволило покрыть её юнит-тестами в Node без браузера.
3. **Промпт по RTCF даёт предсказуемый результат.** Роль/задача/контекст/формат,
   согласованные с правилами проекта, устраняют неоднозначность в ожиданиях.
4. **Progressive enhancement и a11y заложены в контекст промптов**, поэтому
   сайт остаётся работоспособным без JS и доступным с клавиатуры.
